Day 1 of My DevOps Journey
Date: 18 October 2026

1. What Is DevOps?
DevOps is a set of practices, principles, and tools that brings software development (Dev) and IT operations (Ops) closer together.
Its goal is to make software delivery more efficient, reliable, and repeatable throughout the Software Development Life Cycle (SDLC).

I learned that DevOps involves:
- Automation: Automating repetitive tasks such as infrastructure provisioning, testing, and deployments.
- CI/CD pipelines: Automating stages of software integration, testing, and delivery or deployment.
- Monitoring: Tracking application performance, infrastructure health, and system behavior.
- Testing and quality: Integrating automated tests and quality checks into software delivery workflows.
- Troubleshooting: Identifying failures, investigating their root causes, and improving system reliability.
- Continuous improvement: Making the SDLC faster, more consistent, and less prone to human error.
An important distinction I learned is that DevOps isn't just a collection of tools. It's also about collaboration, feedback, automation, and shared responsibility between development and operations teams.

2. Exploring Jira and Task Management
I explored the Jira interface to understand how teams organize and track work.
Jira helps organizations manage tasks, bugs, features, and projects. Teams can assign work to individuals, define priorities, track progress, and visualize workflows.
I learned how tools like Jira help teams maintain visibility into ongoing work and coordinate activities throughout the software development process.
Key takeaway: Jira helps manage the work involved in software development, while DevOps practices help automate and improve the processes used to build, test, deploy, and operate software.

3. Understanding Servers, Virtual Machines, and Hypervisors
I learned the basic concepts behind virtualization and how organizations provision computing resources.
- Server: A physical or virtual system that provides computing resources or services to other systems.
- Virtual Machine (VM): A software-based computer with allocated resources such as CPU, memory, storage, and a virtual network interface.
- Hypervisor: Software that creates and runs virtual machines by managing access to underlying physical hardware.
  
A company can run multiple virtual machines on a physical server, allowing its computing resources to be shared among different workloads.
I also explored how users and automation systems can request virtual machines hosted on company infrastructure.
For example, an engineer might use a command-line interface or an API to request a virtual machine rather than manually configuring a physical server.
Key takeaway: Virtualization allows organizations to provision and manage computing resources without requiring a separate physical server for every workload.

4. Understanding Cloud APIs and Infrastructure Automation
I learned how infrastructure requests can be automated through APIs.
For example, when working with AWS, a developer or infrastructure engineer can send requests to AWS services to create, configure, or manage resources.
These requests can be made using scripts and tools instead of manually performing every operation through a web console.

I explored the following tools and concepts:
Tool	Purpose
AWS CLI	Allows users to interact with AWS services through terminal commands.
AWS SDK	Provides programming-language libraries for interacting with AWS APIs from applications and scripts.
AWS CloudFormation (CFT)	AWS infrastructure-as-code service that provisions and manages resources using declarative templates.
Terraform	An infrastructure-as-code tool that allows infrastructure to be defined, provisioned, and managed across multiple providers.


How they fit together
Consider a scenario where a company needs to create 20 virtual machines.
Doing everything manually would involve repetitive configuration and could introduce inconsistencies.
Instead, an engineer could:
1. Define the required infrastructure.
2. Use a tool such as Terraform or CloudFormation to describe the desired resources.
3. Have the tool communicate with the relevant infrastructure APIs.
4. Provision the resources automatically.
5. Verify the resulting infrastructure and monitor its health.
   
This approach makes infrastructure management more repeatable, scalable, and easier to maintain.
An important distinction: AWS CLI and AWS SDK are ways to interact with AWS services. Terraform and CloudFormation are infrastructure-as-code tools that manage infrastructure through declarative configurations. They solve related but different problems.
Also, Terraform is not limited to AWS. It supports multiple infrastructure providers, although the exact resources available depend on each provider.

5. What I Understand Better After Day 1
Today's learning helped me connect several concepts:

- Jira helps teams organize and track their work.
